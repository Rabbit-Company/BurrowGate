# Custom Challenge Pages

BurrowGate serves an interactive verification page whenever a visitor must complete a browser challenge (for example the `pow-sha256` proof of work). Each site can replace the default page with its own HTML template while keeping the challenge machinery intact.

Unlike custom error responses, a challenge page is always HTML: it has to run JavaScript to solve and submit the challenge, so there is no JSON mode.

## Configuring the template

Open the **Sites** tab, edit a site, and use the **Challenge page** editor. Changes apply to new challenge flows immediately after the site is saved. Use **Reset template** to restore the BurrowGate default; the reset only changes the editor contents, so save the site to apply it.

## Placeholders

Placeholder values are HTML escaped before insertion.

```text
{{title}}            Challenge provider title
{{description}}      Challenge provider description
{{siteName}}         Configured site name
{{host}}             Public request host
{{homeUrl}}          Root URL of the protected site
{{provider}}         Active challenge provider name (e.g. pow-sha256)
{{challengeScript}}  Required. BurrowGate injects the bootstrap + client script here.
```

`{{challengeScript}}` is the only required placeholder. BurrowGate replaces it with the challenge bootstrap and the provider's client module (this fragment is generated by BurrowGate and is not escaped). A template that omits it is rejected on save, because the page could never verify.

## Element contract

The client script for `pow-sha256` looks for two elements and updates them as work proceeds:

- an element with `id="status"` for the current status message
- an element with `id="attempts"` for the running work-unit counter

Both are optional for the page to _load_, but including them gives visitors live feedback. The default template contains both.

## Security

Challenge pages are served with the standard BurrowGate control-plane Content Security Policy, which permits same-origin scripts and workers (the proof-of-work runs in a Web Worker) and the same-origin verification fetch. Placeholder values are escaped, and the injected script is inserted after all placeholder substitution so template values can never smuggle markup into the script region.

The template accepts a complete HTML document up to 131072 characters.
