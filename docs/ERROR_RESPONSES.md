# Custom Error Responses

BurrowGate can return site-specific HTML or JSON for errors generated by the gateway.

This setting applies to errors such as:

- blocked IP, CIDR, or country requests
- blocked route policies
- rate-limit responses
- verification-required API and WebSocket requests
- unavailable HTTP or WebSocket origins
- invalid WebSocket upgrade requests
- disabled WebSocket proxying

Responses returned by the protected origin are not modified.

Errors that happen before BurrowGate can resolve a configured site, such as an unknown public hostname, use the global fallback response.

## Error Codes

Current gateway error codes include:

```text
network_blocked
route_blocked
rate_limited
verification_required
origin_unavailable
websocket_disabled
websocket_upgrade_required
websocket_upgrade_invalid
websocket_origin_unavailable
```

Applications should use the `code` field or `X-BurrowGate-Error-Code` header rather than matching the human-readable message.

## Response Format

Open the **Sites** tab, edit a site, and select one of these formats under **Error responses**:

- `JSON`: return a structured API response containing only selected fields
- `HTML`: render the configured HTML template

Changes apply to new requests immediately after the site is saved.

## JSON Fields

A JSON response can include any combination of these fields:

| Field               | Description                                    |
| ------------------- | ---------------------------------------------- |
| `error`             | Human-readable error message                   |
| `code`              | Stable BurrowGate error identifier             |
| `status`            | Numeric HTTP status code                       |
| `statusText`        | Standard HTTP status description               |
| `requestId`         | Identifier for matching the response with logs |
| `timestamp`         | ISO-8601 response timestamp                    |
| `method`            | HTTP request method                            |
| `path`              | Request path and query string                  |
| `host`              | Public request host                            |
| `siteName`          | Configured site name                           |
| `clientIp`          | Client IP evaluated by BurrowGate              |
| `reason`            | Optional network or policy reason              |
| `routePolicy`       | Matching route-policy name                     |
| `verificationUrl`   | Challenge URL when verification is required    |
| `retryAfterSeconds` | Rate-limit retry delay                         |

Optional fields are omitted when the current error does not provide a value.

At least one JSON field must be selected.

Example minimal response:

```json
{
	"code": "rate_limited",
	"status": 429
}
```

Example detailed response:

```json
{
	"error": "Too many requests",
	"code": "rate_limited",
	"status": 429,
	"requestId": "7cfc1f37-5a5a-4fd6-a1e4-b4711a973a87",
	"path": "/api/search",
	"retryAfterSeconds": 24
}
```

## HTML Templates

The HTML editor accepts a complete HTML document. Placeholder values are HTML escaped before insertion.

Available placeholders:

```text
{{status}}
{{statusText}}
{{code}}
{{error}}
{{requestId}}
{{timestamp}}
{{method}}
{{path}}
{{host}}
{{siteName}}
{{clientIp}}
{{reason}}
{{routePolicy}}
{{verificationUrl}}
{{retryAfterSeconds}}
{{homeUrl}}
```

Optional placeholders render as an empty string when the error does not provide a value.

Use **Reset template** to restore the BurrowGate default template. The reset changes the editor contents; save the site to apply it.

## Security

BurrowGate applies a restrictive Content Security Policy to custom HTML errors:

- scripts are disabled
- frames are disabled
- forms are disabled
- inline styles are allowed
- HTTPS and data images are allowed

The response also includes `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, a stable error-code header, and the request ID.

The generated headers are:

```text
X-BurrowGate-Error-Code
X-Request-Id
```

Rate-limit headers and the `BurrowGate-Verification` header remain available when applicable.
